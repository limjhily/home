# 청약달력

전국 아파트 청약 정보를 **날짜순**으로 보여주는 가벼운 정적 사이트.
`index.html` 파일 하나로 동작한다. 빌드 도구·서버 불필요.

## 화면에 보여주는 것
- 날짜별 타임라인 (특별공급일 기준), 접수중 / D-day / 종료 상태
- 단지 요약: 위치, 총 세대수, 일반공급 세대수, 분양가 범위, 전용면적
- 배지: 전매제한 / 실거주의무 / 전세 가능 여부(실거주의무가 없으면 전세 가능으로 자동 계산)
- 펼치면: 평형별 세대수·분양가·3.3㎡당 단가 표, 전체 일정, 비고, 공고문 링크
- 필터: 지역, 유형(민영/공공), 단지명 검색
- 청약 관련 사이트 링크 모음 (청약홈, LH, SH, GH, 마이홈 등)
- 광고 자리: 상단 배너 1곳, 목록 3번째 카드 뒤 인피드 1곳

## 데이터 수정 방법
`index.html` 안의 `const NOTICES = [...]` 배열만 고치면 된다.

| 항목 | 설명 |
|---|---|
| `total` / `general` | 총 세대수 / 일반공급 세대수 |
| `zone` | 투기과열지구 · 조정대상지역 · 비규제지역 |
| `special`/`first`/`second`/`result`/`contract` | 특별공급·1순위·2순위·당첨발표·계약 일정 |
| `resale` | 전매제한 개월 수 (0이면 없음) |
| `live` | 실거주의무 연수 (0이면 없음 → 전세 가능으로 표시) |
| `units[]` | 타입, 전용면적(㎡), 세대수, 분양가(만원) |

> 현재 들어있는 값은 **샘플 데이터**다. 실제 공고 데이터로 교체해야 한다.

## 실제 데이터 자동 수집 (다음 단계)
공공데이터포털(data.go.kr)의 **"한국부동산원 청약홈 분양정보 조회 서비스"** OpenAPI를
하루 1회 호출해 `NOTICES` 형태의 JSON으로 저장하는 스크립트를 붙이면 수동 입력이 사라진다.
(평형별 분양가·전매제한 등 일부 항목은 API에 없어 공고문 PDF 파싱 또는 수동 보정이 필요하다.)

## 로드맵
1. **v1 (현재)** 정적 사이트 + 수동/자동 데이터 + 애드센스
2. **v2** 관심단지 저장(브라우저 저장), 알림 신청
3. **v3** 로그인 + 내 정보 입력(무주택 기간, 부양가족, 청약통장 가입기간, 소득·자산, 혼인·출산 여부)
   → 가점 자동 계산, 특별공급 유형별(신혼부부·생애최초·다자녀·노부모) 자격 판정과 유리한 유형 추천

## 저장소 구성
```
index.html                     사이트 전체 (샘플 데이터 포함)
data/notices.json              수집 결과 (자동 생성, 있으면 샘플 대신 사용)
data/overrides.json            API에 없는 전매제한·실거주의무 수동 보정
scripts/collect.py             청약홈 OpenAPI 수집기
scripts/build_site.py          검색용 정적 페이지·sitemap 생성
apt/                           단지별 상세 페이지 (자동 생성)
sitemap.xml, robots.txt        검색엔진용 (자동 생성)
.github/workflows/collect.yml  매일 06:00 KST 자동 수집
_headers                       Cloudflare Pages 캐시/보안 헤더
DEPLOY.md                      배포·운영 가이드
```

배포 방법과 API 키 발급 절차는 **[DEPLOY.md](DEPLOY.md)** 참고.

## 알려진 한계 — LH 공공분양의 전매제한 · 거주의무

현재 LH 공공분양 공고(신혼희망타운, 공공분양주택 등)는 이 두 항목이
"확인 필요"로 표시된다. 민영 공고는 100% 자동 추출된다.

### 조사해둔 사실 (2026-09 기준)

| 확인한 것 | 결과 |
|---|---|
| 청약홈 상세 페이지에 공고문 PDF 첨부가 있는가 | **없다.** 민영은 `static.applyhome.co.kr/ai/aia/getAtchmnfl.do` 링크가 있으나 LH 공고에는 없음 |
| 상세 페이지 HTML에 값이 있는가 | **없다.** "입주자모집공고 주요정보" 표는 있지만 전매제한·거주의무 칸이 빠져 있음 |
| 대신 무엇이 있는가 | `apply.lh.or.kr/lhapply/apply/wt/wrtanc/selectWrtancList.do?mi=1027` (LH청약플러스 **공고 목록** 링크) |
| 개별 공고 직링크가 있는가 | **없다.** 목록 페이지로만 연결됨 |

### 자동화하려면 넘어야 할 것
1. LH청약플러스 목록에서 **단지명으로 검색해 매칭**해야 한다.
   청약홈 공고번호(예: 2026820006)와 LH 공고번호 체계가 다르다.
2. 매칭 정확도가 낮으면 **엉뚱한 단지의 값**을 넣게 되므로,
   틀린 값을 보여주느니 "확인 필요"로 두는 편이 낫다는 판단으로 보류했다.

### 급할 때 쓰는 우회로
`data/overrides.json` 에 단지명을 키로 값을 적으면 즉시 반영된다.
LH 공고는 한 달에 몇 건뿐이라 수동 입력도 현실적이다.

```json
{ "인천계양지구 A6블록 공공분양주택(본청약)": { "resale": 60, "live": 5 } }
```

### 참고: 이미 만들어둔 도구
- `scripts/pblanc_pdf.py` — 표(PDF·HTML 공통)에서 기간을 읽는 파서. `--selftest` 로 13종 검증
- `scripts/probe_applyhome.py` — 청약홈 페이지 구조 정찰. Actions 에서 실행


## 검색 노출(SEO) 구조

메인 화면은 자바스크립트로 데이터를 불러온다. 구글은 자바스크립트를 실행하지만
**네이버 검색봇(Yeti)은 실행하지 않아** 빈 페이지로 본다.
그래서 수집 직후 `scripts/build_site.py` 가 아래를 만든다.

- `apt/단지명-공고번호.html` — 단지마다 정적 페이지. 사람들은 "○○아파트 청약"처럼
  단지명으로 검색하므로 이 페이지들이 실제 유입 통로가 된다
- `index.html` 아래쪽 "전체 청약 단지" 목록 — 검색봇이 각 페이지를 찾아가는 통로
  (`<!-- SEO:START -->` 사이는 자동 생성 구간이므로 직접 고치지 말 것)
- `sitemap.xml`, `robots.txt`

### 배포 후 한 번만 해야 하는 등록
- 구글 서치콘솔 https://search.google.com/search-console → 도메인 등록 → 사이트맵 제출
- 네이버 서치어드바이저 https://searchadvisor.naver.com → 사이트 등록 → 사이트맵 제출
- 소유확인 메타태그는 `index.html` 상단의 `google-site-verification`,
  `naver-site-verification` 값에 넣으면 된다 (지금은 비어 있음)
